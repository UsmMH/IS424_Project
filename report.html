Introduction

The digital transformation of fitness and wellness services has accelerated in recent years, with gyms and health clubs increasingly relying on web-based platforms to manage their operations and provide a seamless experience for their members. Scheduling, booking, and class management, once handled through manual registers or phone calls, are now expected to be available at the click of a button.

FitLed is a full-featured web application developed as part of the IS424 Web Application Development course at King Saud University. The system was built using the Django framework (Python) and follows the CRUD (Create, Read, Update, Delete) paradigm, enabling gym administrators and members to interact with a shared database of scheduled gym classes.

Application Theme: FitLed is a male-only gym class booking platform. Members can browse the full schedule of classes, view detailed information about each session, and reserve their spot. Administrators have additional privileges to add new classes and update existing ones.

Project Objectives

  • Implement a complete Django web application with user authentication (registration and login).
  • Provide a structured interface for viewing, booking, adding, and updating gym classes.
  • Enforce role-based access control, distinguishing between regular members and staff administrators.
  • Apply Bootstrap 5 for a responsive and visually consistent user interface across all pages.
  • Demonstrate the many-to-many relationship between users and gym classes through a booking system.

Scope

The application covers the core requirements of a gym class scheduling system: user registration and login, browsing a class schedule, viewing detailed class information, booking a class, cancelling a booking, adding new classes (admin only), and editing existing classes (admin only). The system stores all data persistently in an SQLite database and runs as a local Django development server.

Issue, Problem & Opportunity

The Problem

Traditional gym management relies heavily on manual processes: paper sign-up sheets, phone bookings, and spreadsheet rosters. This approach introduces several well-documented pain points:

  • Overbooking and class conflicts: Without a centralised system, it is easy for a class to exceed its capacity, leading to overcrowded sessions and poor member experience.
  • Lack of real-time visibility: Members have no way to check available spots before arriving at the gym, wasting time and causing frustration.
  • Administrative overhead: Staff must manually update schedules, manage cancellations, and notify members, consuming significant time and effort.
  • No booking history: Members cannot track which classes they have attended or currently have reserved.
  • Scalability issues: As a gym grows, manual systems become unmanageable, limiting the organisation's ability to expand its class offerings.

The Opportunity

A web-based class booking system directly addresses these problems by centralising all data and automating key workflows. The shift from manual to digital management offers the following opportunities:

For Members

Real-time class schedule access, instant booking confirmation, capacity tracking, and a personal bookings dashboard — all from any device with a browser.
For Administrators

Centralised class management, the ability to add or update sessions at any time, automatic enforcement of capacity limits, and a clear view of member engagement.

Why a Django Web Application?

Django is a mature, batteries-included Python web framework that provides built-in solutions for the most common web development challenges — including user authentication, form handling, ORM-based database access, and templating. Its opinionated structure encourages clean, maintainable code and rapid development, making it an ideal choice for a four-week academic project that must deliver a fully functional CRUD application.

Data Models

The application uses two core models stored in SQLite via Django's ORM:

  • GymClass — stores all class details: name, description, instructor, category (yoga, HIIT, strength, etc.), schedule (datetime), duration, capacity, location, and difficulty level.
  • Booking — a through-model implementing the many-to-many relationship between Django's built-in User model and GymClass. Each booking records the user, the class, and the timestamp of the booking.

Access Control

The application enforces two access levels. All pages except /login/ and /register/ require authentication (@login_required). The Add Class and Update Class pages additionally check user.is_staff, blocking regular members and redirecting them with an informative message.

Conclusion

FitLed successfully delivers a complete, functional web application that addresses the real-world problem of gym class scheduling and booking management. All nine project requirements have been implemented and verified, resulting in a clean, consistent, and role-aware application built on the Django framework.

The application provides an intuitive user experience: members can register, browse the full class schedule, view detailed session information, and book or cancel classes with a single click. Administrators have the additional ability to create and update classes, with regular members prevented from accessing those pages at both the URL and UI level.

Lessons Learned

  • Django's ORM is powerful but requires careful model design. Defining the many-to-many relationship between users and classes through a custom Booking through-model — rather than Django's default M2M field — gave us the flexibility to store additional metadata (such as the booking timestamp) and enforce uniqueness constraints.
  • Template inheritance saves significant effort. Creating a single base.html with a consistent navbar, flash messages, and footer, and extending it in all other pages, ensured a uniform look and eliminated duplicated markup.
  • Bootstrap 5 accelerates responsive design. Using Bootstrap's grid system, utility classes, and components allowed us to produce a polished, mobile-friendly layout without writing extensive custom CSS.
  • Separating concerns improves maintainability. Keeping business logic in views.py, data definitions in models.py, and presentation in templates made the codebase easy to navigate, debug, and extend.

Difficulties Encountered

  • Datetime field formatting for HTML inputs. Django stores datetimes in UTC with timezone information, while the HTML datetime-local input expects a specific string format. We resolved this by manually formatting the value in the view with strftime('%Y-%m-%dT%H:%M') before passing it to the update form.
  • Role-based access without a custom user model. Instead of building a custom user model, we leveraged Django's built-in is_staff flag to distinguish administrators from regular members, which simplified the implementation while meeting all functional requirements.
  • Flash message storage. Django's default session-based message storage required active session middleware. Switching to cookie-based storage resolved compatibility issues encountered during development.

Future Improvements

Given more time, the following features would further enhance the system: email confirmation upon booking, a dedicated admin dashboard with analytics, recurring class schedules, waitlist functionality for full classes, and deployment to a production server such as Railway or PythonAnywhere.

Summary: FitLed demonstrates that Django's built-in features — combined with Bootstrap's visual utilities — enable the rapid delivery of a secure, well-structured, and user-friendly CRUD web application within the scope of a four-week academic project.
